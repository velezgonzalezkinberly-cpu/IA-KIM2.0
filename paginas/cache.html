Memoria caché y API Cache

Cómo guarda la PWA sus archivos para funcionar sin Internet.

Esta aplicación usa un service worker (archivo service-worker.js) que se coloca entre la página y el Internet. Para poder abrir el sitio sin conexión guarda archivos en cinco cachés distintos, cada uno con su propio método, todos creados con la Cache API del navegador.

Memoria caché · estático

ia-cbtis260-estatico-v5

Guarda los archivos propios de la aplicación (páginas, CSS, JavaScript, imágenes). Se llena en el evento install con cache.addAll(), así que todo queda disponible desde la primera visita.

API Cache · dinámico

ia-cbtis260-dinamico-v5

Guarda lo que se va pidiendo mientras se navega y no estaba en la lista: fuentes de Google, archivos nuevos, etc. Se llena en el evento fetch con cache.put() y tiene un límite de 40 archivos.

Método 3 · Cache First

ia-cbtis260-modelo-v5

Guarda el modelo de IA (modelo/) y las bibliotecas TensorFlow.js (lib/). Pesan unos 3 MB y casi nunca cambian, así que primero se busca en el caché y solo se va a Internet si no está. Por eso el modelo funciona sin conexión.

Método 4 · Network First

ia-cbtis260-paginas-v5

Cada página HTML que se abre se pide primero a la red, para ver siempre lo más nuevo, y se guarda una copia. Si la red tarda más de 3.5 segundos o no hay Internet, se muestra la última copia guardada.

Método 5 · Cache First con caducidad

ia-cbtis260-imagenes-v5

Guarda las imágenes que no estaban en la lista inicial (por ejemplo las subidas desde PHP). Cada copia lleva su fecha, caduca a los 7 días y hay un máximo de 30 imágenes.

Eventos del service worker

  1. install

    Se abre el caché estático con caches.open() y se guardan todos los archivos de la lista con cache.addAll().

  2. activate

    Con caches.keys() y caches.delete() se borran los cachés de versiones anteriores para no acumular archivos viejos.

  3. fetch

    Cada solicitud pasa por aquí: se busca con caches.match() y, si hace falta, se pide a la red y se guarda con cache.put().

  4. message

    La página puede mandar órdenes al service worker, por ejemplo LIMPIAR_DINAMICO, LIMPIAR_MODELO, LIMPIAR_PAGINAS, LIMPIAR_IMAGENES o LIMPIAR_TODO.

Métodos de la Cache API

MétodoPara qué sirve
caches.open(nombre)Abre un caché o lo crea si no existe.
caches.keys()Devuelve los nombres de todos los cachés.
caches.match(peticion)Busca una respuesta en todos los cachés.
caches.delete(nombre)Elimina un caché completo.
cache.add(url) / cache.addAll(lista)Descarga y guarda uno o varios archivos.
cache.put(peticion, respuesta)Guarda una respuesta que ya tengo.
cache.match(peticion)Busca una respuesta en ese caché.
cache.keys()Lista los archivos guardados en ese caché.
cache.delete(peticion)Borra un archivo del caché.

Resultado

Pulsa «Probar API Cache» para guardar y leer un dato.

Cómo comprobarlo en el navegador

  1. Ver los cachés

    En Chrome abre DevTools (F12) → pestaña Application → Cache storage. Ahí aparecen los cinco cachés con sus archivos.

  2. Probar sin Internet

    En Application → Service Workers activa la casilla Offline y recarga: el sitio debe abrir igual.

  3. Forzar una actualización

    Cambia VERSION en service-worker.js (v5 → v6). Al recargar se crean los cachés nuevos y se borran los viejos.

La documentación completa en texto está en el archivo DOCUMENTACION-CACHE.md del proyecto.
